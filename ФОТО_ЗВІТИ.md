# 📸 ФОТО ЗВІТИ - ДОКУМЕНТАЦІЯ

## 🎯 Огляд Функціоналу

Система фото-звітів дозволяє працівникам документувати процес виконання робіт за допомогою фотографій на трьох етапах:
- **ПЕРЕД** початком роботи
- **ПІД ЧАС** виконання
- **ПІСЛЯ** завершення

Це забезпечує:
- ✅ Контроль якості робіт
- ✅ Прозорість для клієнтів
- ✅ Документування прогресу
- ✅ Захист від непорозумінь
- ✅ Портфоліо виконаних робіт

## 🏗️ Технічна Реалізація

### 1. База Даних

**Файл:** `/app/supabase/migrations/007_add_process_photos.sql`

**Додані поля в таблицю `processes`:**
```sql
ALTER TABLE processes
ADD COLUMN IF NOT EXISTS photo_before TEXT,
ADD COLUMN IF NOT EXISTS photo_during TEXT,
ADD COLUMN IF NOT EXISTS photo_after TEXT,
ADD COLUMN IF NOT EXISTS photos_uploaded_at TIMESTAMPTZ DEFAULT NOW();
```

**Функції:**
- `update_process_photos_timestamp()` - автоматичне оновлення часу зміни фото
- `process_has_photos(process_id)` - перевірка наявності фото
- `get_photo_statistics(user_id)` - статистика по фото

**View:**
- `processes_with_photos` - всі процеси з хоча б одним фото

**RLS Policies:**
- Працівники бачать тільки свої фото
- Менеджери бачать всі фото

## 🔧 Технічні Деталі

### Зберігання Фото

**Формат:** Base64

**Чому Base64?**
- ✅ Не потрібен окремий файловий сервер
- ✅ Швидке впровадження
- ✅ Зберігається в базі даних Supabase
- ✅ Легко отримати та відобразити
- ✅ Працює на всіх пристроях

**Обмеження Base64:**
- ❌ Розмір запису в БД збільшується на ~33%
- ❌ Не ідеально для дуже великих зображень

**Альтернатива (для майбутнього):**
- Використати Supabase Storage Bucket
- Зберігати URL замість Base64
- Більш ефективно для великих файлів

## 📊 Статистика та Аналітика

### Корисні SQL Запити

**1. Скільки процесів з фото:**
```sql
SELECT COUNT(*) FROM processes
WHERE photo_before IS NOT NULL
   OR photo_during IS NOT NULL
   OR photo_after IS NOT NULL;
```

**2. Топ працівників по фото:**
```sql
SELECT
  u.name,
  COUNT(*) as processes_with_photos
FROM processes p
JOIN users u ON p.user_id = u.id
WHERE p.photo_before IS NOT NULL
   OR p.photo_during IS NOT NULL
   OR p.photo_after IS NOT NULL
GROUP BY u.name
ORDER BY processes_with_photos DESC
LIMIT 10;
```

**3. Покриття фото по об'єктах:**
```sql
SELECT
  object,
  COUNT(*) as total_processes,
  COUNT(CASE WHEN photo_before IS NOT NULL THEN 1 END) as with_before,
  COUNT(CASE WHEN photo_during IS NOT NULL THEN 1 END) as with_during,
  COUNT(CASE WHEN photo_after IS NOT NULL THEN 1 END) as with_after
FROM processes
GROUP BY object
ORDER BY total_processes DESC;
```

**4. Використати готову функцію статистики:**
```sql
-- Загальна статистика
SELECT * FROM get_photo_statistics();

-- Статистика для конкретного користувача
SELECT * FROM get_photo_statistics('user-id-here');
```
